# Therapist name alias — ד"ר מיכאל שפרינץ (2026-11-17)

## What Sandra saw
The therapists app showed «הסנכרון למטופלי חוץ נכשל – המטפל/ת אינו/ה מוכר/ת במטופלי חוץ» after
Oren approved a psychiatric follow-up (16/11) as «התקיים», and the patient's counter stayed
«נוצלו 0 מתוך 14».

## Cause
- The therapists roster (synced from staffing) spells him `ד" מיכאל שפרינץ` — the ר is missing.
- `TherapistRates` here has `ד"ר מיכאל שפרינץ` (intake / follow-up rates).
- `_therapistPay` looks the name up **exactly** and fails closed, so `recordSessionOutcome`
  answered `unknown_therapist`: no SessionLog row. The monthly counter («נוצלו X מתוך Y») counts
  `happened` SessionLog rows, so it could not move either.

Not caused by the 2026-11-16 outcome release; the exact-name rule predates it.

## Change (`apps-script/Code.gs` only)
- `THERAPIST_NAME_ALIASES` — an explicit list (one entry) from a misspelt roster name to the
  intended name, both in "key form" (`_therapistAliasKey`: quote-like characters removed, spaces
  collapsed — letters untouched).
- `_canonicalTherapistName(name)`:
  1. an exact `TherapistRates` name is returned as is (the alias is not consulted);
  2. otherwise, if the name's key is listed, it resolves to the **one** `TherapistRates` row whose
     key equals the listed target;
  3. no such row, or more than one → the name is returned unchanged and the receiver refuses
     with `unknown_therapist` exactly as before.
- `_recordSessionOutcome` passes the incoming therapist through it, so the row is priced and
  **stored** under the canonical name (one name per therapist in «תשלומי מטפלים»).

No fuzzy matching, no normalisation-based merge, no rate invented, no sheet or column touched,
no frontend change (no SW bump). One-time sessions are unaffected (their therapist is chosen here,
from this roster).

## Why an alias and not a rename
Correcting the spelling at its source (staffing) is a coordinated migration: the therapists app
treats a changed name as a new therapist and deactivates the old one; his assignments and booked
sessions are stored under the current spelling, and his personal login code is keyed by it. That
needs its own planned change. Remove the alias entry once that rename has been done.

## After release
The refused report is still waiting in the therapists app: «סנכרון» → «נסו שוב» on that line (or
any later approval of his sessions) sends it again.

## Security
Same secret gate, same closed outcome set. The alias can only resolve to a name that already has
a rates row; prototype keys are not names (tested). `npm audit`: 0.

## Tests
`test/therapist-name-alias.test.js` (8, real `Code.gs`): recorded under the canonical name at the
follow-up / intake rate and counted in the month; quote and spacing variants; letter differences
refused; exact name wins; missing / ambiguous target refused; no-pay outcomes; idempotent re-send
and correction; the list's shape; the secret gate. Drill candidate regenerated by its builder.

## Rollback
Revert and redeploy Apps Script. Rows already recorded stay under `ד"ר מיכאל שפרינץ` — the name
`TherapistRates` already uses.
