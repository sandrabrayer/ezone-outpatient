# «מטופלים» split by patient type — 2026-11-18

Branch `claude/patient-type-tabs-20261118`, base `claude/youthful-volta-laarnk` @ `18fa434`.

## Why

Sandra asked to separate day-community patients (קהילה יומית) from psychiatrist patients
(one-time or as needed), each in its own tab. Decisions (2026-11-18):

1. **Three types**, plus «הכול»: `day_community` → «קהילה יומית», `individual` →
   «טיפולים פרטניים» (every other package or ongoing therapy), `psychiatric` → «פסיכיאטר».
2. **Automatic, with a manual override** that Vered sets on the card.
3. A day-community patient who also books a psychiatrist session stays in **«קהילה יומית» only**.

## Rules (`public/patient-type.js`, first match wins)

| # | Condition | Type |
| --- | --- | --- |
| 1 | `patientTypeOverride` is one of `PATIENT_TYPES` | the override («ידני» on the card) |
| 2 | the plan (`serviceType`) has ליווי יומי בקהילה / legacy מרכז יום | `day_community` |
| 3 | the plan is non-empty and every treatment is מעקב פסיכיאטרי / אינטייק | `psychiatric` |
| 3b | any other non-empty plan | `individual` |
| 4 | no plan, and every one-time session of this patient is psychiatric | `psychiatric` |
| 5 | otherwise (incl. one-time sessions not loaded) | `individual` |

Rule 4 covers a lead booked for a psychiatric one-time service (`CHANGELOG-one-time-psychiatric.md`):
the lead becomes a per-session patient with a blank plan. A session is psychiatric by its
`clinicalTreatmentType` — the source maps all four psychiatric services to «מעקב פסיכיאטרי» /
«אינטייק» — so **no catalog key ships in the browser** (`test/package-ui-assets.test.js`).

## What changed

### UI (`public/index.html`, `public/app.js`, `public/style.css`)

- «מטופלים» opens with `#clientTypeTabs`: «הכול N», «קהילה יומית N», «טיפולים פרטניים N»,
  «פסיכיאטר N». Counts = ACTIVE patients (סיים טיפול / לא פעיל excluded, as before); search and
  the service filter narrow the list, never the counts.
- The existing service filter row stays. Inside a type tab it lists only the treatment types that
  occur there, and hides itself when it could not narrow anything. Switching type resets it.
- Under «הכול» each card shows its type chip; in any tab a manual choice shows «ידני».
- עריכה → תוכנית טיפול → **«סוג מטופל»**: אוטומטי / קהילה יומית / טיפולים פרטניים / פסיכיאטר,
  with a hint «אוטומטי כרגע: …». Rolled back with the other fields if the save is refused.
- The «היום שלי» patient locator resets the type tab to «הכול» so the patient is always found.
- Fail-soft: if `patient-type.js` does not load, no type tabs are shown and everything is listed
  as before; an override is never lost.

### Source (`apps-script/Code.gs`)

- `CLIENTS_HEADERS` += `patientTypeOverride` — **appended at position 42**, physically unwritten
  on the live sheet, no migration; mirrored at the end of `CLIENTS_REMOVED_HEADERS` (a tombstone
  keeps it).
- `PATIENT_TYPES` + `_patientTypeOrBlank` (closed set, trimmed, anything else → blank).
- `_saveAll`: same rule as `complementaryType` — a sent value is validated, a payload without the
  key keeps the sheet value, a sent blank clears it. Not in `OPS_CLIENT_MONEY_KEYS`.
- **Not projected**: `getTreatmentPlans`, the one-time feed and the debt feed are unchanged — the
  therapists app and the dashboard see nothing new.

### Not changed

Billing, renewal, debt status, charges, payments, payment IDs, credits, SessionLog, payouts,
the package catalog, the therapists contract. A psychiatric patient on a monthly package keeps
his renewal cycle; a per-session patient already has none.
