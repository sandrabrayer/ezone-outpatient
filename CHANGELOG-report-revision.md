# Session outcome — report order (`reportRevision`), 2026-11-15

> Candidate hardening supersedes the unrestricted no-revision/equal-revision compatibility statements below. A versioned row rejects an unversioned external event; equal revisions require matching persisted result/identity. Read CHANGELOG-report-order-hardening.md. This remains unreleased.

## Problem
`_recordSessionOutcome` upserts SessionLog by `sessionId`; the last write wins. The therapists
app pushes an approved outcome outside its lock. If report A is approved, then corrected to B
and approved again, and A's push arrives AFTER B's, Outpatient ended with A — wrong pay and
wrong credit for the session. Reproduced with both real Code.gs files in the therapists repo's
paired test (`test/paired-out-sync.test.js`) against `172eb2f`.

## Change
- Therapists (its own PR) sends `reportRevision`: the approved report's server-owned time.
- `SESSION_LOG_HEADERS` gains `reportRevision` at the END (append-only; `_ensureSheet` writes
  the header cell on the first write; existing rows read '').
- `_recordSessionOutcome`, inside the existing ScriptLock, after the row lookup and BEFORE the
  credit engine or any write:
  - incoming revision older than the stored one → `{ ok:false, reason:'stale_report_revision' }`;
  - equal or newer → written; the stored revision becomes the incoming one;
  - no incoming revision → as before; the stored revision is kept;
  - present but unreadable (not a date, > 40 chars) → `invalid_report_revision`, before the lock.
- The forwarded-pay freeze, credit reversal and all pay/price tables are untouched.
- One-time sessions go through `_otsRecordOutcome` as before.

## Compatibility / rollout
Either side can deploy first. Old therapists + new Outpatient: no revision → today's behaviour.
New therapists + old Outpatient: the extra field is ignored. Remaining window: a push sent by a
pre-upgrade therapists script that is still in flight carries no revision.

## Security
Same `SESSION_OUTCOME_SECRET` gate, fail-closed; the revision is validated; nothing new is
logged; no new endpoint.

## Tests
`test/report-revision.test.js` (real Code.gs in the sandbox): late older push refused with row,
pay and credits untouched; in-order correction; idempotent re-send; no-revision behaviour;
unreadable revision; one-time path unaffected. Header-position tests updated; the operational
drill candidate (`test-support/google-operational-drill-candidate.gs`) regenerated by its builder
because it embeds Code.gs helpers. Full suite 2371/2371.

## Rollback
Revert the merge and redeploy Apps Script: the extra column stays in the sheet harmlessly
(append-only) and is ignored by the previous code.
